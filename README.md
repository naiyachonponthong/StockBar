# StockBar — ระบบสต๊อกสินค้า รองรับเครื่องยิงบาร์โค้ด

Google Apps Script + Google Sheets · Bootstrap 5 + jQuery · ledger-based inventory

---

## 1. ติดตั้ง

1. สร้าง Google Sheets ใหม่ 1 ไฟล์ (ว่างเปล่า) → เมนู **ส่วนขยาย > Apps Script**
2. ลบ `Code.gs` เดิมทิ้ง แล้วสร้างไฟล์ตามนี้ (คัดลอกเนื้อหาจากโฟลเดอร์นี้ทั้งหมด)

| ไฟล์ในโปรเจกต์ | ชนิดไฟล์ใน Apps Script |
|---|---|
| `Code.gs` | Script |
| `index.html` | HTML |
| `css_main.html` | HTML |
| `js_core.html` | HTML |
| `js_master.html` | HTML |
| `js_stock.html` | HTML |
| `js_reports.html` | HTML |
| `js_advanced.html` | HTML |
| `appsscript.json` | Manifest (เปิดจาก ⚙️ Project Settings > Show appsscript.json) |

3. สร้างโฟลเดอร์ใน Google Drive สำหรับเก็บรูป แล้วคัดลอก **Folder ID** จาก URL มาวางที่บรรทัด
   `FOLDER_ID: ''` ใน `Code.gs` (ถ้าไม่ใช้รูป ข้ามได้)
4. รันฟังก์ชัน `initializeSheets` หนึ่งครั้ง เพื่อสร้างชีตทั้งหมด และอนุญาตสิทธิ์
5. **Deploy > New deployment > Web app**
   - Execute as: **Me**
   - Who has access: ตามที่ต้องการ
6. เปิด URL ที่ได้ → เข้าระบบด้วย `admin` / `admin1234` แล้วเปลี่ยนรหัสผ่านทันที

### ตั้งแจ้งเตือนอัตโนมัติ (ไม่บังคับ)
Apps Script > Triggers > Add Trigger แล้วตั้ง 2 ตัว (Time-driven, Day timer)
- `dailyLowStockReport` — สรุปสินค้าใกล้หมด
- `dailyExpiryReport` — สรุปล็อตหมดอายุ/ใกล้หมดอายุ

แล้วใส่ LINE Notify Token หรืออีเมลในหน้า **ตั้งค่า**

## 2. ตั้งค่าเครื่องยิงบาร์โค้ด

รองรับเครื่องยิง **USB / Bluetooth แบบ HID (keyboard wedge)** ทุกรุ่น ไม่ต้องลงไดรเวอร์

1. ยิงบาร์โค้ดตั้งค่าในคู่มือเครื่องเพื่อให้ **suffix = Enter (CR)** อย่างเดียว
2. เปิดหน้ารับเข้า / เบิกออก / ตรวจนับ — ช่องรับบาร์โค้ดจะโฟกัสอัตโนมัติตลอด คลิกที่ไหนก็เด้งกลับ
3. ยิงได้เลย ไม่ต้องคลิกช่อง

ระบบแยก "ยิงด้วยเครื่อง" กับ "พิมพ์มือ" โดยวัดความเร็วระหว่างคีย์ (< 35 ms/คีย์ = เครื่องยิง)

**โหมดการยิง 3 แบบ** (ปุ่มบนแผงสแกน)
- `ยิงรัว +1` — ยิงซ้ำสินค้าเดิม จำนวนบวกเพิ่มอัตโนมัติ (โหมดเริ่มต้น)
- `ยิงแล้วใส่จำนวน` — เด้งช่องกรอกจำนวนทุกครั้ง
- `เช็คข้อมูล` — ไม่เพิ่มลงรายการ แต่โชว์ราคา/ยอดคงเหลือทุกคลัง

**สแกนด้วยกล้องมือถือ** — ใช้ได้ที่หน้ามือถือ (`liff-web`) เท่านั้น เพราะ Google Apps Script
บล็อกการเข้าถึงกล้องในหน้าเว็บที่รันอยู่ใน iframe ของตัวเอง

**ยิงแล้วไม่พบ** — ในหน้ารับเข้า/ปรับปรุงยอด ระบบจะเปิดฟอร์มสร้างสินค้าใหม่ให้ทันที
พร้อมบาร์โค้ดที่ยิงไป กรอกชื่อแล้วบันทึกจบ ไม่ต้องออกจากหน้า

## 3. โครงสร้างข้อมูล (JSON-per-row)

ทุกชีตมี 1 คอลัมน์ หัวตารางคือ `<ชื่อ>_json` และเก็บ 1 เรคคอร์ดต่อ 1 แถวเป็น JSON

| ชีต | เก็บอะไร |
|---|---|
| Users / Sessions | ผู้ใช้และเซสชันเข้าระบบ |
| Products | สินค้า: รหัส ชื่อ หมวด หน่วย min/max ต้นทุนเฉลี่ย ราคาขาย |
| Barcodes | บาร์โค้ด → สินค้า + หน่วย + จำนวนต่อหน่วย (1 สินค้ามีได้หลายบาร์โค้ด) |
| Categories / Locations / Suppliers | ข้อมูลหลัก |
| **Movements** | **บัญชีเคลื่อนไหว — แกนกลางของระบบ ทุกการเข้า-ออกอยู่ที่นี่** |
| Balances | ยอดคงเหลือ `productId\|locationId` (cache สร้างใหม่ได้ตลอด) |
| DocIn / DocOut / DocTransfer / DocCount / DocAdjust | หัวเอกสาร + รายการสินค้าในเอกสาร |
| Settings / Logs | ตั้งค่าและประวัติการใช้งาน |

**หลักการ:** ยอดคงเหลือไม่เคยถูกแก้ตรงๆ ทุกอย่างเกิดจาก Movements
ถ้ายอดเพี้ยน กดปุ่ม **คำนวณยอดใหม่** ในหน้ายอดคงเหลือ ระบบจะสร้าง Balances ใหม่ทั้งหมดจาก Movements

## 4. ฟังก์ชันงาน

| งาน | รายละเอียด |
|---|---|
| **รับเข้า** | เลือกผู้จำหน่าย + คลัง → ยิงบาร์โค้ด → ใส่ราคาทุน → บันทึก → ต้นทุนเฉลี่ยถ่วงน้ำหนักคำนวณใหม่อัตโนมัติ |
| **เบิก-จ่ายออก** | ตัดสต๊อกจากคลังต้นทาง เตือนทันทีถ้าของไม่พอ (ปิดการเตือนได้ในตั้งค่า) |
| **โอนย้ายคลัง** | ตัดคลังต้นทาง + เพิ่มคลังปลายทาง ในธุรกรรมเดียว |
| **ตรวจนับสต๊อก** | ยิงนับทีละชิ้น → ระบบเทียบยอดระบบ vs นับจริง → แสดงผลต่าง → บันทึกแล้วปรับยอดให้อัตโนมัติ |
| **ปรับปรุงยอด** | ของเสีย / สูญหาย / หมดอายุ / ยอดยกมา (ใส่บวกหรือลบ) |
| **ยกเลิกเอกสาร** | คืนยอดกลับทั้งหมด และบันทึกรายการกลับไว้ในบัญชีเคลื่อนไหว ตรวจสอบย้อนหลังได้ |
| **พิมพ์สติกเกอร์** | CODE128 ผ่าน JsBarcode ปรับขนาด มม. ได้ · สินค้าที่ไม่มีบาร์โค้ดใช้รหัสสินค้าแทนอัตโนมัติ |
| **นำเข้า CSV** | `code,name,barcode,unit,minQty,salePrice,avgCost` |
| **ล็อต + วันหมดอายุ** | เปิดที่ฟอร์มสินค้า ติ๊ก "ติดตามล็อต" · ตอนรับเข้าระบุเลขล็อต (ใส่อายุสินค้าไว้ ระบบคำนวณวันหมดอายุให้) · ตอนจ่ายออกระบบตัด **FEFO** อัตโนมัติ หมดอายุก่อนออกก่อน พร้อมโชว์ตัวอย่างการตัดก่อนบันทึก |
| **ซีเรียลรายชิ้น** | ติ๊ก "ติดตามซีเรียล" ที่สินค้า · รับเข้า/จ่ายออกต้องยิงซีเรียลทีละชิ้น จำนวนในเอกสารเท่ากับจำนวนซีเรียลอัตโนมัติ · กันซีเรียลซ้ำและกันจ่ายซ้ำ · ตามรอยได้ว่าชิ้นไหนเข้าเอกสารไหน ออกเอกสารไหน |
| **ใบสั่งซื้อ (PO)** | เปิด PO → กดปุ่มรับเข้าตาม PO ระบบดึงรายการค้างรับลงตะกร้าให้ทันที → รับแล้วตัดยอดค้างและปิด PO ให้อัตโนมัติ · ยกเลิกใบรับเข้าก็คืนยอดค้างรับกลับ |

### รายงาน
การ์ดสินค้า (stock card แบบมียอดคงเหลือสะสม) · ยอดคงเหลือแยกคลัง · รายงานเข้า-ออก ·
มูลค่าสินค้าคงคลังแยกหมวด · สินค้าไม่เคลื่อนไหวเกิน N วัน · **ล็อตคงเหลือ** ·
**ใกล้หมดอายุ/หมดอายุแล้ว พร้อมมูลค่าเสี่ยง** · **ทะเบียนซีเรียล** · ส่งออก CSV ได้ทุกตัว

### หน้ามือถือผ่าน LINE (LIFF)
โฟลเดอร์ `liff-web/` เป็นเว็บ static แยก โฮสต์บน GitHub Pages คุยกับ Apps Script ผ่าน JSONP
ทำให้ใช้สแกนเนอร์ของ LINE และล็อกอินอัตโนมัติด้วยบัญชี LINE ได้
ขั้นตอนติดตั้งอยู่ใน `liff-web/README.md`

### สิทธิ์ผู้ใช้
| บทบาท | ทำอะไรได้ |
|---|---|
| admin | ทุกอย่าง + จัดการผู้ใช้ + ดู log |
| manager | ทุกงานสต๊อก + ปรับปรุงยอด + ยกเลิกเอกสาร + ตั้งค่า |
| staff | รับเข้า / เบิกออก / โอนย้าย / ตรวจนับ / เพิ่มสินค้า |
| viewer | ดูอย่างเดียว |

## 5. หมายเหตุทางเทคนิค

- **ต้นทุน:** ค่าเฉลี่ยถ่วงน้ำหนัก (Weighted Average) คำนวณใหม่ทุกครั้งที่รับเข้า
  `ทุนใหม่ = (คงเหลือเดิม × ทุนเดิม + รับเข้า × ทุนที่ซื้อ) ÷ ยอดรวม`
- **การเขียนทุกครั้งใช้ LockService** ป้องกันคนหลายคนบันทึกชนกัน
- **การอัปเดตยอดคงเหลือทำเป็นชุดเดียว** (อ่านชีตครั้งเดียว เขียนครั้งเดียวต่อเอกสาร) เอกสาร 50 รายการก็ไม่ช้า
- ฝั่งเว็บ cache ตาราง barcode ไว้ในหน่วยความจำตอนเปิดหน้า → ยิงรัวได้ไม่ต้องรอ server
- ทุกไฟล์ `js_*.html` ห่อ `<script>` ของตัวเอง และใช้ `\x3c/` ใน string ที่สร้าง HTML

## 6. สิ่งที่ยังต่อยอดได้

ระบบขายหน้าร้าน (POS) ต่อยอดจากใบเบิกออก · เชื่อมบัญชี/ภาษี ·
รับคืนสินค้าจากลูกค้า (RMA) อิงซีเรียล · ป้าย QR ประจำชั้นวางเพื่อนับตามโซน ·
ประมาณการจุดสั่งซื้อจากยอดขายเฉลี่ย (reorder point อัตโนมัติ)
